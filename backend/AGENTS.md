# 后端开发规范

## FastAPI 规范

- 所有后端代码必须遵循 FastAPI 的推荐实践：使用 `APIRouter` 组织路由，使用 Pydantic 模型校验请求和响应数据，并通过依赖注入管理数据库会话、认证和权限等横切逻辑。
- 路由层仅负责参数接收、调用业务层和组装响应；业务逻辑不直接堆放在路由函数中。
- 新增接口应纳入现有 `/api/v1` 路由聚合结构，避免绕过项目的入口和版本管理。

## 代码注释

- 所有方法必须编写简明注释或文档字符串，说明其职责、关键参数、返回值及必要的副作用或异常。
- 所有路由处理函数必须编写注释或文档字符串，说明接口用途、主要输入与返回结果。
- 所有模型类必须编写注释或文档字符串，说明对应的业务实体、表或数据结构含义。
- 注释应解释业务意图和约束，避免重复代码表面含义。
- 中文注释

## 接口文档

- 每个 FastAPI 路由必须补充可生成 OpenAPI/Swagger 文档的说明，包括 `summary`、`description` 和合理的 `response_description`。
- 请求参数、路径参数、查询参数和请求体字段应通过 `Query`、`Path`、`Body`、`Field` 等声明提供描述和示例（适用时）。
- 路由须声明准确的 `response_model`；接口存在可预期错误响应时，应在 `responses` 中注明状态码和业务含义。
- 标签（`tags`）和接口说明使用一致的业务术语，确保 `/docs` 中的接口文档可直接供前后端联调使用。

## 错误响应约定

- `/api` 命名空间内的业务错误不得直接通过 HTTP 错误状态码返回给前端。
- 错误状态码必须写入响应体的 `code` 字段，响应体统一包含 `code`、`message`、`data`，其中 `data` 为 `None`；HTTP 状态码统一返回 200。
- `message` 尽量使用中文响应
